Bring your own clustering¶

New to mdCIF? Run 1_basic first. It explains each step (PCA, clustering, medoids, modes) and what ends up in the file. This notebook changes only the clustering step.

mdCIF does not care how the frames were grouped into states. All it needs is one label per frame: frames with the same number belong to the same state, and -1 marks a frame that belongs to no state (noise). Everything after that is the same as in 1_basic: one medoid per state, the state's population and precision, its own modes, and the file.

Your clustering can come in one of two ways:

Your clustering is… Pass it as What the file records about it
a scikit-learn-style estimator (anything with a fit_predict method) cluster(traj, estimator) its name, the parameters you changed and the software version, all automatically
labels made anywhere else: your own script, cpptraj, GROMACS, a Markov state model… cluster(traj, labels=...) the method and software you name

We try one of each on the GB1 run from 1_basic and write two mdCIF files. Everything this notebook writes goes into this folder:

File What
gb1_gmm.cif states from a Gaussian mixture (way 1)
labels_rmsd.txt our own labels, one per frame (way 2)
gb1_rmsd.cif states from those labels
figures/ Fig. 1 (vector PDF + 600-dpi PNG)

It runs in under a minute; the trajectory (2 GB) is read once.

1. A scikit-learn-style estimator¶

Any object with a fit_predict method works, whether one of scikit-learn's clustering classes or a class of your own. cluster gives it each frame's position on PCs 1–3 (n_pcs= changes how many PCs; features="cartesian" gives it the superposed Cα coordinates instead).

Our example is a Gaussian mixture, which describes the map as a few overlapping bell-shaped clouds. You choose how many (3 here), and every frame goes to its most likely cloud, so, unlike HDBSCAN, it leaves no frame as noise.

2. Your own labels¶

Labels can come from anywhere: the per-frame cluster numbers written by cpptraj or GROMACS, the discrete trajectory of a Markov state model, or a few lines of your own code. They follow two rules:

  1. One integer per analysed frame, in order. Here that means the 17,683 frames read with start=25_000, step=10. If your tool labelled every saved frame, take the same slice: all_labels[25_000::10].
  2. -1 = noise. The frame belongs to no state and is left out of every model. The other numbers are only names: mdCIF renumbers the states by size.

As an example, here is a rule a folding study might use: the Cα RMSD of each frame to the NMR structure (3GB1 model 1). Below 5 Å the protein is folded, above 8 Å it is in the misfolded state of 1_basic (its model 2), and the few frames in between are on their way from one to the other, so they count as noise.

In [5]:
import gemmi

from mdcif.reference import load_reference
from mdcif.trajectory import superpose

nmr = gemmi.read_structure(str(load_reference("3GB1").path))   # downloaded once, then cached
nmr_ca = np.array([[a.pos.x, a.pos.y, a.pos.z] for res in nmr[0][0] for a in res
                   if a.name == "CA"])
fitted = superpose(traj.raw, nmr_ca)[0]                        # every frame onto the NMR Cα
rmsd = np.sqrt(((fitted - nmr_ca) ** 2).sum(axis=2).mean(axis=1))

labels = np.full(traj.n_frames, -1)      # noise, unless a rule below says otherwise
labels[rmsd < 5] = 0                     # folded
labels[rmsd > 8] = 1                     # misfolded
np.savetxt("labels_rmsd.txt", labels, fmt="%d")   # one per line: what mdcif build --labels reads
print(f"folded {np.mean(labels == 0):.1%}, misfolded {np.mean(labels == 1):.1%}, "
      f"noise {np.sum(labels == -1)} frames")

folded 95.2%, misfolded 4.7%, noise 6 frames

Next, name your method, so that readers of the file know where the states came from. Here method and software come from the clustering: block of provenance.yaml, which mdcif build --labels reads too; you can also type them in directly. features="cartesian" records that the labels were computed from coordinates (an RMSD), not from the PCs.

3. The two files side by side¶

Read back with read_mdcif, each file says how its states were made (the clustering step in ihm_modeling_post_process, with its software) and keeps the map to draw them on (_mdcif_projection).

Figure 1. The same 5,000 stored frames on PCs 1–3, coloured by state: a, Gaussian mixture (gb1_gmm.cif); b, the RMSD rule (gb1_rmsd.cif). Large dots: the models (medoids). Drawn from the two files alone.

The Gaussian mixture splits the folded basin into two states of about the same size (models 1 and 2, medoids 2.5 and 3.1 Å from 3GB1) and keeps the misfolded state apart (model 3). The RMSD rule sees only folded and misfolded: the same two states HDBSCAN finds in 1_basic, with the six noise frames taken out of model 1. Which split is right depends on the question you are asking (substates of the folded protein, or folded versus misfolded); either way, the file records how its states were made.

The same from the command line¶

mdcif build takes labels from a file (.npy, or text with one integer per line):

mdcif build ../../data/3gb1/meld/3gb1_HMR.prmtop ../../data/3gb1/meld/meld.nc.001 \
    --provenance provenance.yaml --start 25000 --step 10 \
    --labels labels_rmsd.txt --output gb1_rmsd.cif

The method and software come from the clustering: block of the YAML, and --labels-method overrides the method. Estimators are Python-only. 3_cli covers the command line in full.
